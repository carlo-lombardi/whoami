01 / work

What I build and run

Since 2025 I have worked at Fónua, a telecoms fulfilment, repair and logistics operation in Dublin, as an IT Support Engineer. The title is narrower than the job: systems, cloud identity and automation engineering across multiple sites.

The pieces below are illustrative models built for this page and run on synthetic data. The real systems are internal.

A knowledge system with hybrid retrieval

I designed and built a retrieval-augmented (RAG) knowledge system on ChromaDB over resolved incidents and internal documentation. Retrieval is hybrid: dense vector similarity and BM25 keyword matching, fused with reciprocal rank fusion, so a query finds both the passage that means the same thing and the one that contains the exact error code.

from the CV: “RAG knowledge system … hybrid retrieval (dense vectors + BM25, reciprocal rank fusion)”

        Both rankers run in your browser over the sections of this page. BM25 is the real algorithm. The similarity ranker compares character trigrams and stands in for dense embeddings, because no model is shipped to your browser; it is what catches the typo.

        An MCP server the whole IT team uses

        I delivered a remote MCP (Model Context Protocol) server that exposes that knowledge base to the wider IT team. It runs in production: any colleague's AI client can list the tools and call them, instead of the knowledge living on one laptop.

        Agents that are not allowed to break things
        
          
        I built specialised AI agents for triage, solution verification and pre-change risk analysis. They work behind guardrails: a hook inspects every command before it runs and blocks destructive operations, so an agent can investigate freely without being able to delete what cannot be recovered.

        Identity, from first day to last
        
          
        I administer Microsoft 365 and Entra ID: the identity lifecycle of joiners, movers and leavers, Intune enrolment and compliance, Azure RBAC, and Azure VPN Gateway with SSO and MFA. Access follows group membership, so changing a person's role rewires what they can reach, and leaving removes all of it.
        
          
        from the CV: “identity lifecycle (joiner, mover, leaver), Intune enrolment and compliance, Azure RBAC”
        
        
        
        
        
          
        One person, three events
        
          
        
            
            
            
          
        
          
          
        Joiner: account created, licence assigned, added to groups, laptop enrolled. Access arrives through the groups, not by hand.
        
        
        
      
        

      
        
        
        
          
        Certificates that expire on my schedule, not theirs
        
          
        I own the certificate and PKI lifecycle across five platforms, including SAML SSO and API certificates on Azure App Service. Production changes are sequenced for risk: non-production first, written confirmation, an out-of-hours rollout, and validation through Application Insights telemetry before anyone calls it done.
